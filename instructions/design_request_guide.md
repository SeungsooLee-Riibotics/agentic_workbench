# 시스템 설계 요청 가이드

이 문서는 Codex에게 시스템 설계를 요청할 때, 원하는 결과를 빠르고 정확하게 얻기 위한 요청 템플릿이다.

## 사용법 (복붙용)

1) 아래 항목을 순서대로 채운다.
2) 불명확한 항목은 "미정(확정 필요)"로 남긴다.
3) 하나의 요청에서 다 처리되지 않으면, 1~2개 항목씩 단계적으로 진행한다.

## 필수 입력 항목

### 0. 요청 목표
- 어떤 문제를 해결할 시스템인지 2~3줄로 정리
- 성공 기준(DoD, acceptance criteria)

### 1. 배경/맥락
- 대상 제품/서비스/로봇/플랫폼
- 사용자 또는 운영 대상(운영자, 장비, 외부 시스템)
- 기존 시스템과의 연동 여부

### 2. 기능 요구사항
- 핵심 기능 목록 (필수 / 선택 / 보류)
- 핵심 사용자 시나리오(정상 흐름, 예외 흐름)
- 성능 목표(지연, 처리량, 동시성)

### 3. 비기능 요구사항
- 신뢰성(장애 허용 범위, 복구 목표)
- 보안(인증/권한/통신 보안)
- 확장성(노드 수/장비 수/데이터 증가량)
- 운영/배포 제약

### 4. 제약사항
- 하드웨어 제한, OS/프레임워크/언어 제약
- 예산/일정/인력 제약
- 반드시 사용해야 하는 기존 기술 스택 또는 금지 기술

### 5. 데이터·인터페이스
- 외부 API, 메시지 토픽, DB/파일 스키마 등
- 메시지/엔드포인트 예시
- 에러 코드 정책

### 6. 우선순위
- 먼저 설계할 모듈/컴포넌트 우선순위
- 먼저 구현해도 되는 범위 / 나중에 확장할 범위

### 7. 산출물 형식 요구
- 원하는 수준 지정
  - 개요 수준(High-level) / 세부 수준(Sequence/ERD/Deployment)
  - 다이어그램 필요 여부 (텍스트 대체 가능)
  - 코드 스캐폴드 포함 여부

### 8. 검토 조건
- 내가 직접 확인할 포인트(예: 보안 위험, 실패 모드, 대체안)
- 반드시 반영하고 싶은 점(예: 단일 장애점 제거, 모듈 분리)

## 요청 템플릿

아래 형식으로 요청하면 된다.

```text
[프로젝트명]
목표: 
성공 기준: 

[범위]
포함: 
제외: 

[요구사항]
기능:
비기능:
제약:

[현재 구조]
저장소/디렉토리/기존 코드 링크:

[원하는 산출물]
1) 시스템 맥락 개요
2) 아키텍처 제안 2안 + 각 장단점
3) 핵심 컴포넌트 설계(입력/출력/에러 처리)
4) 데이터 흐름과 예외 플로우
5) 도입 우선순위/단계별 구현 계획(짧은 스프린트 기준)
6) 구현 시 주의사항(리스크/롤백 포인트)
```

## 단계별 진행 제안(1회에 과부하 방지)

- 1단계: 문제 정의 + 제약 정리
- 2단계: 아키텍처(구조/모듈 분해)
- 3단계: 데이터 플로우 + 인터페이스 설계
- 4단계: 실패 시나리오/복구 + 모니터링 설계
- 5단계: 구현 순서와 산출물 정리

---

참고: Codex에게 "지금 바로 구현 코드부터"를 요구하기보다 위 항목을 먼저 채워서 요청하면, 설계-구현 정합성이 좋아진다.
