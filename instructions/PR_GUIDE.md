# PR 작성 가이드 (GitHub Pull Request, 작성자용)

이 문서는 **작성자 입장에서 내 PR 본문을 구성할 때** 사용하는 가이드다.
리뷰어가 다른 사람 PR을 intake 하거나 판정하는 용도가 아니다. 그런 경우에는 `pr_review_intake_gate.md`를 사용한다.

## 목표
이 PR은 **무엇을 왜 바꾸는지**를 짧고 명확하게 설명해야 한다.  
세부 diff 나열보다, `커밋 단위 + 변경 영향 + 검증` 중심으로 정리한다.

---

## 1) PR 제목
- 형식 예시: `feat: ris_base image setup + 개발환경 개선`
- 요약형으로 1줄 작성 (예: `chore: devcontainer 정리와 ris_base 배포 안정화`)

## 2) 본문 기본 템플릿
아래 형태로 작성하면 리뷰어가 한 번에 이해하기 쉽다.

### PR 개요
- (1~2줄) 이 PR의 목적과 효과를 한 문장으로 작성

### 변경 사항
- `항목` : `변경 내용` : `변경 이유`

### 커밋 기반 요약
- `커밋 해시` - `커밋 메시지` - `의미`
- 최신 순/시간순 중 하나로 정렬

### 영향 범위
- 빌드/배포, 테스트, 운영, 의존성에 미치는 영향

### 검증/테스트
- 빌드 명령, 테스트 스크립트, 실행 확인 항목

### 체크리스트
- [ ] 영향 받는 서브모듈/컴포넌트 확인
- [ ] 문서/스크립트 변경사항 반영
- [ ] 불필요한 미반영 파일(미추적 파일 등) 처리 확인

---

## 3) 지금 PR(예시) 요약용 초안
`version/1.2.5` 기준으로 바로 사용할 수 있는 최소 요약:

### PR 개요
ris_base 컨테이너/배포 인프라 정비와 개발 환경 개선, 리뷰 반영 및 안정화를 한 번에 정리한 PR이다.

### 핵심 변경
- ris_base 관련: Docker 자산/CI/설정 보강 및 g++ 반영
- 개발 환경: devcontainer 범용성 개선, clang-tidy 빌드 태스크 예외 패키지 추가
- 정적/코드 스타일: shfmt/code-rabbit 권고 반영
- 안정화: 특정 소프트웨어 업데이트 커밋의 revert 반영 및 base image 대기 정책 보완
- 운영 보조: `watch_ros_humble_logs.sh` 추가

### 참고
- 커밋 로그 기반으로 구성했으며, 파일별 diff는 부록 또는 별도 섹션으로 추가하면 된다.

## 4) PR 작성 시 실수 방지 체크
- 작업 트리에 있는 `m` 상태(서브모듈 내부 수정)와 `??`(미추적) 파일을 본문에 명시
- PR에 포함하지 않을 변경은 `추가/제외 항목`으로 분명히 적기
- “무엇을 위한 변경인지”가 우선되고, “어떻게 바뀌었는지”는 보조로 적기
